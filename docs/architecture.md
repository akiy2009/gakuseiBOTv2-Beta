# 内部構成

## 起動ライフサイクル

1. `main.py` が `.env` を読み込み、prefix、Cog の警告閾値、任意チャンネル ID を初期化します。
2. `DISCORD_TOKEN` があることを確認して Discord Gateway に接続します。
3. `on_ready` で `cogs/` 以下の Python ファイルを走査し、各 Cog を extension として読み込みます。
4. スラッシュコマンドを同期し、Bot のステータス更新ループと Cog のファイル監視を開始します。
5. 再接続時に `on_ready` が再実行されても、Cog の一括読み込み、コマンド同期、ステータスループ、ファイル監視を重複起動しないようフラグを保持します。

## Cog の配置と読み込み

- `cogs/normal/`: 通常利用者向けコマンド。
- `cogs/admin/`: 管理・運営向けコマンド。
- Cog は `async def setup(bot)` で登録します。
- `__init__.py`、テスト用ファイル、`tests/` 内のファイルは自動読み込み対象から除外します。
- 読み込みに失敗した Cog は `bot.load_failures` に記録され、別の Cog の読み込みを妨げません。
- `data/heavy_cogs.json` に Cog 名またはモジュール名を記載すると、自動読み込み対象から除外できます。

## 開発時のファイル監視

`watchdog` は `cogs/` 内の Python ファイルの作成・変更を監視し、変更された Cog を再読み込みします。再読み込みは開発を容易にする機能であり、本番環境でのコード配信・更新を代替するものではありません。運用環境への更新はレビュー済みの Git commit とデプロイ手順で行ってください。

## HSS 連携の境界

`cogs/normal/timetable.py` は HSS のクライアントを任意依存として初期化します。4 つの HSS 設定がそろわない場合は外部 API に接続しません。接続に失敗した場合も、状態を Cog 内に記録して通常の Bot 起動を継続します。HSS token はログに出さず、時間割コマンドの応答は ephemeral（実行した利用者だけに表示）です。

この連携は、環境変数で指定された 1 校・1 学年・1 クラスを表示する用途です。ユーザー個人ごとの HSS アカウント認証や token の保存機能は実装していません。
